# Always-Valid A/B Testing

Watch an online experiment run live, and see when its result is safe to act on.

Players arrive every few seconds, split at random between the standard reward schedule and a **Starter Bonus**. The page shows what happens to them, and an analyst verdict above everything else: **Keep collecting**, **Ship**, or **Don't ship**. The verdict comes from an always-valid confidence sequence, so it stays correct no matter how often you look.

> The page is currently called *Live A/B Lab* (its public name is still open). **Questline** is a fictional rewarded-gaming marketplace. All data is either generated by a known-truth simulator or recorded from synthetic personas (model responses, not people).

**Live page:** https://dannyredel.github.io/always-valid-ab-testing/

## Methods

| Question | Method | Built in |
|---|---|---|
| Can we look at the result at every update? | Always-valid confidence sequence (normal mixture), tuned to the planned size | [notebook 03](notebooks/03_always_valid.ipynb), checked against GrowthBook's `gbstats` |
| How many players do we need? | Break-even lift from the bonus economics; sequential power by simulation | [notebook 04](notebooks/04_power_and_planning.ipynb) |
| Is the split fair, are the groups alike, is anyone harmed? | Always-valid sample-ratio check (Dirichlet-multinomial), standardised differences, segment intervals widened for multiplicity | [notebook 05](notebooks/05_checks_and_segments.ipynb) |
| Can we decide sooner? Does it pay? | CUPAC (CUPED with a model prediction from pre-sign-up signals); a value guardrail derived from the lift | [notebook 06](notebooks/06_regression_adjustment.ipynb) |
| Who should get the bonus? | Causal forest (econml), DoubleML subgroup effects, honest sample splitting, calibration tests, policy value | [notebook 08](notebooks/08_targeting.ipynb) |

## Run it locally

```bash
uv venv && uv pip install -e ".[notebooks,dev,article]"   # Python engine, notebooks, tests
python -m pytest                                          # reference engine
cd web && npm ci && npm run dev                           # the page
npm test                                                  # parity with Python, stream checks
```

## Principles

1. **Ten-second rule.** Someone with no statistics background understands the page in ten seconds.
2. **Four things on screen by default:** the two experiences, the arriving players, the verdict, the chart. Everything else opens on request.
3. **No invented numbers.** Every figure comes from the engine; every validity claim is backed by a test or simulation in this repo.
4. **Static site.** No backend, no database, no live model calls.
